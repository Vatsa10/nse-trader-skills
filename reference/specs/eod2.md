# Spec from eod2 and its siblings (GPL-3.0 sources, clean-room notes, no code copied)

Studied: eod2 (every file), NseIndiaApi (the `nse` package eod2 imports: transport, retry, cookies, the NSE class), eod2_data (README, meta.json, isin map, breadth CSV), stock-pattern (loaders, pattern rules, state diffing), SwingTrend (trend algorithm). Ours: trader-data/data.py in full, plus every reader of trader/data in the other scripts.

## 1. What it does

eod2 is a command-line NSE end-of-day pipeline. Each run it walks every calendar day since the last sync, drops holidays, downloads that day's equity bhavcopy, delivery report and index snapshot, appends one row per stock (OHLCV, series, trade count, quantity per trade, delivery quantity) to per-symbol CSVs and one row per index, then rewrites history for splits and bonuses taken from NSE's corporate-actions feed. It follows symbol renames through ISIN, rolls the day back on any failure, retries late delivery reports, and a second script computes market-breadth series. A separate chart tool and delivery CLI sit on top (not relevant to us). eod2_data is the published CSV output; stock-pattern and SwingTrend are independent analysers that read those CSVs.

## 2. How the pieces connect

**Chain.** NSE website and archives -> NseIndiaApi (`nse`, pinned ~5.1) -> eod2 (`init.py`) -> eod2_data folder (`daily/*.csv`, `meta.json`, `isin_symbol_map.json`, `market_tracker.csv`) -> consumers: eod2's own chart/delivery tools, stock-pattern (pattern scanner), SwingTrend (trend library, no hard link; the user feeds it OHLC frames). The data folder is a git submodule/zip so code and data release separately; `meta.json` carries a `data-version` that eod2 refuses to run against if it differs from its expected value (schema gate).

**NseIndiaApi behaviour (the shared plumbing).**
- Headers: desktop Firefox User-Agent, `Accept-Language`, `Referer` of a quote page. Cookies: loaded from a Mozilla-format file in the work folder; if none, one GET of `https://www.nseindia.com/option-chain` fetches them; they are saved on exit.
- Throttle: 3 requests per second shared by API calls and file downloads. Timeout 15 s.
- Retry: up to 5 retries on timeouts, connect/read errors, protocol errors, and HTTP 429/502/503/504. Wait = 2^attempt seconds with full random jitter, capped at 8 s; a `Retry-After` header (seconds or HTTP date) replaces it, same cap. A protocol error also rebuilds the session first.
- Files: HTTP 404 on a download becomes a distinct "file unavailable / not yet published" error and is never retried. Other 4xx raise. Downloads stream to `<name>.part` and are renamed on success; an existing file of that name is returned without any freshness check. Zip/gz are unpacked (first member) and the archive deleted.
- Endpoints eod2 uses, in the order a run touches them: (1) cookies page above; (2) `GET /api/circulars?from_date=DD-MM-YYYY&to_date=...&dept=CMTR` -> `{"data":[{sub, cirDisplayDate, circFilelink...}]}`; (3) pending-delivery retry and the day loop: `GET /api/holiday-master?type=trading` -> `{"CM":[{tradingDate:"26-Jan-2026", weekDay, description}], ...}`; `GET /api/corporates-corporateActions?index=equities|sme|mf&from_date=&to_date=` -> list of `{symbol, series, subject, exDate "DD-Mon-YYYY", isin, faceVal, recDate...}`; for the current day only, `GET /api/daily-reports?key=CM` and `key=INDEX` -> `{currentDate:"DD-Mon-YYYY", CurrentDay:[{fileKey,...}]}` with keys `CM-UDIFF-BHAVCOPY-CSV`, `CM-BHAVDATA-FULL`, `INDEX-SNAPSHOT`; archives: `https://nsearchives.nseindia.com/content/cm/BhavCopy_NSE_CM_0_0_0_YYYYMMDD_F_0000.csv.zip` (UDiFF, from 2024-07-08; earlier `/content/historical/EQUITIES/YYYY/MON/cmDDMONYYYYbhav.csv.zip`), `/products/content/sec_bhavdata_full_DDMMYYYY.csv` (delivery), `/content/indices/ind_close_all_DDMMYYYY.csv` (indices). Breadth script adds `/archives/equities/bhavcopy/pr/PRDDMMYY.zip` (inside, a CSV whose name contains "mcap" with Symbol, Series, Category, Last Trade Date).
- Other library calls worth knowing: `GET /api/allIndices` (per index last, pe, pb, dy, advances, declines, plus exchange-wide advances/declines/unchanged, live); `GET /api/equity-stockIndices-adu?index=NIFTY 50` (advances/declines/unchanged); `GET /api/historicalOR/vixhistory?from=&to=` and `/api/historicalOR/indicesHistory?indexType=NAME&from=&to=` (fields `EOD_INDEX_NAME, EOD_OPEN/HIGH/LOW/CLOSE_INDEX_VAL, EOD_TIMESTAMP "15-DEC-2025"`, newest first); equity history via `/api/NextApi/apiClient/GetQuoteApi?functionName=getHistoricalTradeData&symbol=&series=&fromDate=&toDate=` in 100-day chunks, rows with `CH_*` prices, `CH_TOT_TRADED_QTY`, `CH_TOTAL_TRADES`, `VWAP`, `CH_ISIN`, `mTIMESTAMP`; `GET /api/equity-stock-indices?index=NIFTY 500` for constituents.

**eod2 day loop (order).** Load config and meta -> check data-version -> special-session scan (circulars since last check, default 5 days back) -> retry pending delivery dates -> for each next date: stop if the date is in the future, or today before 16:00 IST -> skip if holiday (Sunday always; holiday list from meta, refreshed once per run when needed; Muhurat "Laxmi Pujan" entries count as open; dates registered as special sessions override) -> refresh the forward corporate-actions cache -> for today, check report readiness and stop (exit 1) if the bhavcopy or index report is not yet published (delivery is optional) -> download bhavcopy and index file -> a 404 or network error: on a Saturday that is a past date, treat as closed and continue; on any other day stop without advancing -> delivery file, on failure append the date to a pending list -> append stock rows, then index rows -> apply splits/bonuses with ex-date equal to the day -> on any exception truncate today's last line from every file and stop -> delete downloads, advance `lastUpdate`, save the ISIN map -> once a year-old file has no new row, delete it.

**State files.** `meta.json`: lastUpdate, market_breadth_last_update, year, holidays{DD-Mon-YYYY: name}, DLV_PENDING_DATES, special_sessions, special_sessions_last_update, equityActions/smeActions/mfActions plus expiry stamps, data-version. `isin_symbol_map.json`: symbol->ISIN and ISIN->list of {symbol, from_date, to_date, action}. `market_tracker.csv`: Date, PCT_50, PCT_200, NET_NEW_HIGHS, AD_LINE, MCCLELLAN_OSC, NET_ADV_RATIO, FAST_EMA, SLOW_EMA. Stock CSV: `Date,Open,High,Low,Close,Volume,Series,TOTAL_TRADES,QTY_PER_TRADE,DLV_QTY`, file name = lowercase symbol (SME series get `_sme`), index files = lowercase index name with spaces (`nifty 50.csv`). Raw downloads are archived by year (nseBhav, nseDelivery, nseIndices).

**Downstream contract.** stock-pattern and the chart tool read `<lowercase symbol>.csv` with a Date index and Open, High, Low, Close, Volume (extra columns ignored); weekly bars come from resampling Monday-Friday weeks. The relative-strength benchmark and breadth chart read the index files (`nifty 50`, `nifty 500`) from the same folder. stock-pattern keeps a per-watchlist state file keyed symbol-pattern so a rerun shows only patterns that are new since last time. SwingTrend wants frames with Open, High, Low, Close in that column order and at least 40 bars (60 recommended).

**Mapping to ours.**
- eod2 daily/ <-> our trader/data/daily/<SYM>.csv (+ .adj.csv). Ours is symbol-by-symbol on demand with a source fallback chain; eod2 is whole-market, one bhavcopy per day, NSE only.
- NseIndiaApi <-> our Session in data.py (cookie priming, polite gaps, one 401 re-prime, retries only for Yahoo).
- meta.json holidays/special sessions <-> our hard-coded tables, in THREE places: data.py (2024 to 2026, `CALENDAR_YEARS`), trader-alerts/alerts.py (2026 only) and trader-scanner/scan.py (its own `NSE_HOLIDAYS`, "holiday list covers 2026 only" warning). All three break in January 2027.
- market_tracker.csv, delivery columns, index files, corporate-action factors, trend structure: absent here.
- Consumers: scanner longterm, invest technicals, backtest, portfolio last-close and alerts/news cache fallbacks all read `daily/<SYM>.adj.csv` else `.csv` by header name (`date,open,high,low,close,volume`; backtest and invest require those names, scanner and portfolio use DictReader). Extra columns in those files are tolerated by readers but `data.py write_daily` rewrites the fixed six-column header and `read_daily` drops extras, so new per-day fields must go in sibling files.

## 3. Ranked ideas for our system

### 1. One shared, self-updating trading calendar plus report readiness. Both. Effort M. Urgent (breaks Jan 2027)
- Cache `trader/data/calendar.json`: `{fetched_at, years:{"2027":{"2027-01-26":"Republic Day"}}, special_sessions:{"2026-11-08":"Muhurat"}, last_circular_check}`.
- Holidays: `GET /api/holiday-master?type=trading` via the cookie-primed `nse_api`; take the `CM` list, convert `tradingDate` (DD-Mon-YYYY) to ISO. An entry whose description contains "laxmi pujan" is a special session, not a closure. Refetch when the year is missing, when a date being tested is a listed holiday and the list is older than one day, or on `--refresh`.
- Circulars: `GET /api/circulars?from_date=&to_date=&dept=CMTR`, since the last check (first run: 5 days back). Lowercased subject containing "trading holiday" and "on account of" adds a holiday; containing "live trading session" adds a special session. Pull the date from the subject text with our existing `parse_date` plus a "Weekday, Month DD, YYYY" form; if no date parses, record a warning and do not guess.
- Resolution order for `trading_day(d)`: special session true; weekend false; calendar.json; built-in tables. Built-ins remain the offline fallback.
- Readiness: for the current day ask `/api/daily-reports?key=CM` and `key=INDEX`; ready when `CM-UDIFF-BHAVCOPY-CSV` (and optionally `INDEX-SNAPSHOT`) is in `CurrentDay`; a `currentDate` other than today means closed. If the call fails fall back to the 18:00 rule. A 404 on today's bhavcopy URL is "not published yet", never an error.
- Where: new small module section in `trader-data/data.py` (`calendar` subcommand, `doctor` probes both endpoints); data.py `trading_day`/`CALENDAR_YEARS` read it; `trader-alerts/alerts.py` and `trader-scanner/scan.py` load the same JSON when present (they stay stdlib-only and offline-safe by falling back to their tables).
- Test: fixture holiday-master JSON with 2027 dates and a Sunday "Diwali Laxmi Pujan" entry, fixture circulars JSON with one "Trading Holiday on account of ..." subject and one unparsable subject. Assert `trading_day` for 2027-01-26 (false), the Muhurat Sunday (true), the circular date (false), and one warning for the unparsable subject; assert a failed fetch leaves the built-in answer.

### 2. Delivery analytics (we already download the data and discard it). Both. Effort M
- Source: the `sec_bhavdata_full_DDMMYYYY.csv` that `Bhav.day` already fetches (our fixture shows the columns: SYMBOL, SERIES, DATE1, TTL_TRD_QNTY, NO_OF_TRADES, DELIV_QTY, DELIV_PER, with spaces after commas and `-` for blanks; DELIV_PER is often `-`, so compute it).
- Extend `parse_bhav` to also return trades and delivery quantity. Series EQ, BE, BZ. For BE/BZ (trade-to-trade) delivery is the full volume. `-` becomes empty, never 0. Skip symbols ending `-RE` (rights).
- Store in `trader/data/delivery/<SYM>.csv`: `date,volume,trades,deliv_qty,deliv_pct,qty_per_trade,series`. qty_per_trade = volume / trades (2 dp; trades 0 or empty -> empty).
- Metrics over the last 30 sessions that have data, window including the latest day: DQ = deliv_qty / mean(deliv_qty), TQ = qty_per_trade / mean(qty_per_trade), VOL = volume / mean(volume). Flag IM ("institutional money") when DQ > 1.2 and TQ > 1.2 on a non-T2T series. Bands on DQ: >= 2 strong, >= 1.5 high, > 1 above normal. Fewer than 5 values in the window: report "not enough delivery data".
- Late files: if the delivery file for a day 404s, append the date to `delivery/pending.json`; retry on each run; drop it with a warning once it is more than 5 days old. UDiFF fallback has no delivery fields, so those days stay empty.
- Where: `trader-data/data.py` (`delivery` command; a cache-fill for the symbols named); `trader-scanner/scan.py` adds tag `delivery_spike` (IM on the latest day) and number `dq`; `trader-invest/invest.py` shows IM days among the last 30 sessions as a hint; intraday: the pre-market scan lists yesterday's IM names first.
- Test: 31-row delivery fixture for one symbol, 30 days at 100 and a last day at 300, trades constant. Expect DQ about 2.8, IM true, band strong. Add a BE row with `-` delivery: deliv_qty equals volume. Add a day with `-` on EQ: stored empty, excluded from means.

### 3. Corporate-action driven exact split/bonus adjustment. Long-term. Effort M
- Today `.adj.csv` exists only when Yahoo supplied it; bhavcopy/NSE-API data is unadjusted and backtest guesses from a fixed ratio list (a 1:7 split or a 5:4 bonus is missed).
- Feed: `GET /api/corporates-corporateActions?index=equities&from_date=&to_date=` (also `sme`). Query by explicit date ranges (30-day chunks) covering the cache's whole span, store `trader/data/actions.json` with `fetched_through`, refetch only newer ranges plus the last 7 days. Note eod2 uses a rolling 8-day window renewed every 7 days, which can lag after a long gap and miss ex-dates; do not copy that.
- Lowercase the subject. Only EQ, BE, BZ. Split: subject contains "split", "splt" or "consolidation": from that keyword on, take the first two numbers (decimals allowed) with only letters, spaces, `/`, `-`, `.` between them; factor = first / second (old face value over new; consolidation gives a factor below 1). Bonus: subject contains "bonus" and a ratio `a:b` (spaces allowed); factor = 1 + a/b. Skip bonus subjects mentioning deb, pref, ncrps or dvr. Both in one subject: multiply. Everything else (dividends, buybacks, rights) is ignored.
- Rebuild, never mutate: `.adj.csv` = raw `.csv` with, for each action, rows dated before exDate having O/H/L/C divided by the cumulative factor (2 dp; eod2 snaps to 0.05, which distorts low-priced stocks) and volume multiplied.
- Verify each action: adjusted close on exDate over the previous adjusted close should be in 0.67 to 1.5, else warn "possible adjustment failure"; no row on exDate: warn "unverified"; no number matched: warn and skip; duplicate dates in the file: refuse. All-or-nothing per symbol.
- Where: `trader-data/data.py` (`adjust` command, run automatically after `daily` for non-Yahoo sources); `backtest.detect_corporate_actions` stays as a cross-check and is silenced for symbols with a `.adj.csv`.
- Test: 8-row raw CSV, a "Face Value Split (Sub-Division) - From Rs 10/- Per Share To Re 1/- Per Share" ex on row 4 (close 1000 to 100) and "Bonus 3:2" ex on row 7 (factor 2.5), plus a "Bonus 1:1 NCRPS" and a dividend record that must be ignored. Assert adjusted closes of rows 1-3 are original / 10 / 2.5 and rows 4-6 original / 2.5, volumes scaled up, both verifications pass.

### 4. Index snapshot, valuation and VIX. Both. Effort S-M
- URL `https://nsearchives.nseindia.com/content/indices/ind_close_all_DDMMYYYY.csv`: Index Name, Open/High/Low/Closing Index Value, Volume, P/E, P/B, Div Yield; `-` means null. Store `trader/data/index/<slug>.csv` (`date,open,high,low,close,volume,pe,pb,div_yield`), slug = lowercase name with `/` and `:` replaced by `-`. Backfill via `/api/historicalOR/indicesHistory` (index name upper case, one-year chunks, reverse to ascending) and India VIX via `/api/historicalOR/vixhistory`; live context from `/api/allIndices` (also gives exchange-wide advances/declines).
- Valuation rule from eod2: Nifty 50 P/E >= 25 flagged expensive, <= 20 cheap, else neutral; thresholds configurable and printed as a rule of thumb. Add the percentile of today's P/E within cached history once 250 rows exist.
- Where: `trader-data/data.py` (`index` command; `doctor` probes the archive); `trader-invest` prints a market valuation line beside its earnings-yield test; `trader-scanner`/`trader-risk` can print VIX as intraday context (high VIX, wider stops).
- Test: two-day index CSV fixture with a row whose P/E is `-` and a "Nifty Bank / X" name. Assert null, slug, classification at 25.0, and percentile on a 300-row synthetic PE series.

### 5. Market breadth series from our own cache. Both (regime filter). Effort M
- Universe: symbols in the Nifty 500 list that have a cached `.adj.csv` (use adjusted data, otherwise a split fakes a new low). Per date, per symbol with a bar that day:
  - SMA50 and SMA200 of closes including today; count a symbol only when it has the history. pct50 = above50 / counted50 * 100 (2 dp); same for 200.
  - New high if today's High exceeds the max High of the previous 252 sessions (today excluded); new low likewise. Needs 252 prior bars.
  - advance if Close > previous Close, decline if lower; unchanged only in `total`.
- Series: net_new_highs = running sum of (new highs minus new lows); net_adv_ratio = (adv - dec) / total * 100; ad_line = running sum of (adv - dec) / total (a ratio line, not counts); fast EMA 19 and slow EMA 39 of net_adv_ratio, alpha = 2 / (n + 1), each seeded with the plain average of its first n ratios and first emitted on the n-th day; McClellan oscillator = fast - slow, first emitted on day 39. Skip dates with total 0.
- Where: `trader-scanner/scan.py` subcommand `breadth` writing `trader/data/breadth.csv`, one-line regime note in the scanner header and `trader-invest`. Intraday: a single `/api/allIndices` call gives the live advance/decline count, no per-stock fetch.
- Caveat to print: current constituents only, so history is survivorship-biased.
- Test: 3 symbols, 4 days, SMA lengths overridden to 2 and 3, by-hand adv/dec/total, one EMA seed (average of first n ratios) and one update step.

### 6. Relative strength against the index. Long-term. Effort S
- Join stock and index closes on common dates. Dorsey RS = stock close / index close * 100. Mansfield RS = (RS / SMA(RS, n) - 1) * 100; n = 52 on weekly bars (classic), 22 on daily, 24 monthly, 8 quarterly. Positive and rising means outperforming. Benchmark: `nifty 50` from idea 4 (or Yahoo ^NSEI).
- Where: `trader-scanner/scan.py longterm` adds `mansfield_rs` and tag `rs_positive`; `trader-invest` technical pillar.
- Test: closes 100,110,121 against a flat index of 100, n=2: Dorsey 100,110,121; Mansfield on row 3 = (121 / 115.5 - 1) * 100 = 4.76.

### 7. Mechanical swing-structure trend (SwingTrend). Both (trailing stop, trend filter). Effort M
- Pure sequential state machine over bars (high, low, close), stdlib friendly. State: trend (none/up/down), running high, running low, swing-point high (SPH) or low (SPL), change-of-character level (CoCh), bars since last swing point, leg count.
- Start: first bar sets high and low. The first bar whose close is above that high sets trend UP (CoCh = first bar's low); below that low sets DOWN (CoCh = first bar's high).
- UP trend: a bar making a higher high resets the counter and updates the running high (and restarts the retracement low). A bar failing to make a higher high marks the running high as SPH, starts tracking the lowest low since. A close above the SPH is a break of structure: if a retrace threshold is set (default 5%) and the pullback low was less than that fraction below the SPH it is ignored (no new CoCh); otherwise CoCh = that pullback low and the leg count rises. A close below CoCh reverses to DOWN: CoCh becomes the old running high, leg count resets. DOWN is the mirror image.
- Outputs: trend, SPH/SPL, CoCh, bars_since, leg_count, is_sideways (bars_since > 20), is_trend_stable (more than 40 bars seen, 60 recommended).
- Use: CoCh is a mechanical trailing stop for long-term holds (8% threshold on weekly bars for long holds, none for short-term); "uptrend with a pullback of 4 to 15 bars" is a scan.
- Where: `trader-scanner/scan.py` tag `uptrend_pullback`; `trader-exit` and `trader-portfolio` show CoCh as a stop reference; `trader-backtest` can add a `swing_trend` strategy (buy on break of structure, sell on CoCh close).
- Test: 12 hand-made bars (10 rising, a 3-bar pullback of 4%, a close above the prior high, then a close below the pullback low). Assert trend UP, SPH set, CoCh equals the pullback low, then DOWN on the last bar with leg_count 0. Repeat with threshold 5% to show the 4% pullback is ignored.

### 8. Sync state and transport hardening. Both. Effort S-M
- Retry for NSE archive/API requests in `Session.get`: on 429/502/503/504 and timeouts retry up to 5 times, wait 2^attempt seconds with random jitter, cap 8 s, honour `Retry-After` (seconds or HTTP date, same cap). A 404 on an archive file is never retried. Today only Yahoo retries.
- Persist cookies between runs (stdlib `http.cookiejar.MozillaCookieJar` in `trader/data/`), load without discarding session cookies, re-prime on 401 once. Optionally prime with the `/option-chain` page as the library does.
- Download to `<file>.part` then rename (already atomic for our CSVs; add for any raw bhavcopy archive).
- Weekday-failure rule for multi-day fills: a missing file on a day the calendar says is open is a hard stop that does not advance the cache; on a Saturday of a past date it means closed, which also catches unannounced special sessions.
- Add the legacy bhavcopy URL (`/content/historical/EQUITIES/YYYY/MON/cmDDMONYYYYbhav.csv.zip`) to `bhav_urls` for dates before 2024-07-08 so `--years max` works; its columns (SYMBOL, SERIES, OPEN, HIGH, LOW, CLOSE, TOTTRDQTY, TIMESTAMP, ISIN) are already covered by `parse_bhav`'s name table.
- Add the NextApi history call as a second NSE-API attempt (our `/api/historical/cm/equity` path is older than the library's); it returns total trades, VWAP and ISIN as bonus fields.
- Schema gate: write `trader/data/cache_meta.json` with a `schema` number and refuse (with the fix command) if a newer layout is found.
- Where: `trader-data/data.py` only. Test: fake transport returning 503 twice with `Retry-After: 1`, then 200 (assert two sleeps capped at 8 s and one success); a 404 asserting a single attempt.

## 4. Considered and set aside
- Cheap pattern ideas from stock-pattern (VCP, double top/bottom from pivots with 6 bars each side, median bar range as tolerance, ATR 15) and a "show only new setups" state file: worth a later pass on scanner, but they depend on idea 7 pivots and are low-confidence rules; the state-diff keyed symbol+pattern+start date is a good small add once more setups exist.
- Swing support/resistance levels (pivot highs/lows needing a second touch within the median bar range): superseded by idea 7 for stops.
- ISIN symbol-rename tracker: needs the UDiFF file (sec_bhavdata_full has no ISIN); real value only for renamed tickers; defer.
- AmiBroker export, matplotlib charts, drawing tools, plugin loader that imports arbitrary user code: off-scope or a security risk.
- Deleting CSVs idle for 365 days: creates survivorship bias, bad for backtests.
- Append-only rows plus truncate-last-line rollback: our whole-file atomic writes already cover it.
- Rounding adjusted prices to 0.05: distorts low-priced stocks.
- SME series files (SM/ST/SZ): outside our liquid universe.
- Integrity checker script: `validate_daily` already covers it.
- Tail-reading CSVs without parsing the whole file: our caches are small.
